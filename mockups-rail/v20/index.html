Window row: the field and the mark come from the source pane, the focused one when it has a branch, and that is what the box opens. A pane in the same repo carries no mark, because the window row already says it. A pane in a different repo carries its own one cell mark, and clicking it opens that pane's facts, so the second repo is no longer invisible. A window whose panes all share a repo looks exactly as it does today.

3. What this costs

  • The box becomes pane keyed. Today it is keyed by window and reads the window's source pane. A per-pane mark needs the box to remember a pane id and read that pane, which is the real work in this drawing.
  • One cell on a differing pane row, and no extra cell on the common case.
  • A width change on the thin rail, plus a rule for a stored four.
  • Nothing in the wire. Every fact is already per pane.

4. What I would do

Take the five cell thin rail with the git cell, and take the per-pane mark in the full rail. Both say the same thing in the place the fact lives, and neither needs a new probe. The six cell thin rail is only worth it if you want a question visible in the thin rail, which today it is not.
