dm rail · v12 · the git field in a fixed slot

A field after a variable label cannot align, so the field moves into a fixed slot at the right: twelve cells for the numbers, one for the mark, one cell of air, then the state at the margin. Every window row now puts its + in the same cell, its - in the same cell, its mark in the same cell, and its state in the last cell. The label takes what is left and elides.

22 rows. Three of them have something to see in git, so three carry a field and a mark. The rest draw twelve blank cells and a blank mark cell, which cost nothing visually and keep the columns still.

The field: six cells for added lines, six for removed, each left aligned from its sign, so the signs stack. A count past five digits is written compactly, +1.2k, so a digit is never cut and the box holds the exact number.

The mark: one cell after the field, present when the worktree has work or is out of step with its upstream, blank when there is nothing to see, and present on hover for a clean row so the box is always reachable.

Same slot, different numbers: the two signs, the mark and the state are in the same cells on every row. A row with nothing to show keeps the slot and draws nothing in it.

What changed, and why this is not the old row

  • The order is fixed, not ragged. The old row printed +12 -3 wherever the label ended. Here the numbers own a column, and the eye learns it once.
  • The git mark is one cell. It is a target, so it needs a cell and nothing else. The old three cell glyph padding is gone.
  • The state still owns the margin. Git occupies the slot before it, so the margin keeps its one meaning: what needs me.
  • Absence is still information. A blank field and a blank mark say the worktree is clean and nothing is waiting.
