dm rail · v10 · git only where there is something to see

The counts go, and the mark stays only where it means something. The rail does not restate what the box already says: it shows one glyph when the worktree has work in it, or when the branch is out of step with its upstream. A clean row at rest says nothing about git at all, and under the pointer the mark appears, so the box is always one click away.

A clean row: at rest, then with the pointer on it. Below it, a dirty row the same width. The glyph is one cell, so showing it on hover costs a clean row nothing.

22 rows, and two of them carry a git mark. The rail went from five marks and five pairs of counts to two marks. Everything else about the row is unchanged, so compare this against v9 pane for pane.

Keeps: the full tree, one scannable state column, and the box itself: every fact it holds is still one click away, on every row, hovered or not.

Loses: the line counts, and the dot that used to say dirty. What is left is presence: a mark means the worktree has uncommitted work, or the branch is ahead of or behind its upstream. A row with no mark has nothing to see in git.

Why the mark still earns its place. It is the only thing in the rail that says this worktree has uncommitted work, and it is the target for the box. Two states, one glyph: present when there is something to see, absent when there is not. Under the pointer the mark appears on any window row, in the quiet tone, so a clean window can still open its box.
