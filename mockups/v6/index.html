dm rail · git target and float

The rail keeps the dirty dot and the +/- counts and stops printing the branch. Git detail moves to a clickable [git] target at the right edge of each window row, which opens a facts float beside the rail. A linked worktree no longer prints the same string twice, because the branch leaves the row.

Ladder. 34 cells: counts stand down, the dot and the chip hold. 26: the label elides to keep half the row. 20: the chip sits directly after the label with one space, so it costs 6 cells and still fits. 5. What the click does

click the chip      the float opens on that row, the chip paints filled
click another chip  the float moves, one float per rail, never two
click elsewhere     the float closes
esc                 the float closes and returns focus to the pane it came from
rail scroll         the float follows its row, and closes when the row leaves the view

Pointer events only. No prefix key is taken. The rail already carries click targets for panes, windows and workspace folds, so the chip is one more hit box, and a click on the chip must not also focus the window. The float is the same panel.FloatingPane the ask form uses, so the outline, shadow and dismissal path are shared.

6. Cost, in the code we have

wire.Pane         head sha, head subject, ahead, behind   (new fields, omitempty)
server_labels.go  one more probe: log -1, rev-list --left-right, upstream
rail.RailStats    drop the branch segment, append the chip
rail line         chip is one more right-hand segment, same rent ladder
float             a small facts renderer over panel.FloatingPane

The probe is the only real cost. A rail line is painted from the cached gitInfo, and the head subject plus upstream counts need one more git call per worktree. Two options: fold them into the existing rev-parse round trip with git log -1 --format=%h %s and a separate rev-list --left-right --count @{u}...HEAD, or fetch them lazily on the click and paint the float from a fresh probe. Lazy is cheaper and the click already costs a round trip, but the float then differs from the row on a stale cache. Say which you want and the next version shows it.
