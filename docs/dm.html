dm

Introduction

dm is a durable terminal multiplexer in one binary. One process is the server: it owns the panes and their pty state, and it keeps running after you leave. A second mode is the TUI client, which draws the panes and sends actions. A third is the CLI, which sends the same actions to the same server, so a script and a hand on the keyboard drive one surface. Detach and reattach, and the shells keep running.

A workspace is s1, s2, and so on. A window is w1, w2. A pane is its window id plus p and a per-window sequence: w2p3 is the third pane opened in window 2. Ids are readable and constructible, and a counter only moves forward, so a closed id is never reused.

Where this page comes from: dm html renders it from the Go tables cliCommands, manActionFields, manActionNames, keymap.LoadDefault().HelpEntries() and the configdoc tables and the prompt-mark section.

Themes

A theme file is $XDG_CONFIG_HOME/dm/themes/<name>.kdl. The theme node in config.kdl names one, and no theme node keeps the built-in theme. Every block and every key is optional: the file reads over the built-in theme, so it carries only what it changes. A block or key given twice, an unknown block or key, a colour that is not #rrggbb, or a glyph that is not one cell wide is an error. This page paints itself from the built-in theme's palette, so the page and the terminal agree.

Prompt marks

dm copies a command's output with prefix y and dm yank. The Enter dm forwards marks where that output starts; the shell's OSC 133 marks make both edges exact. Without them the copy starts after the echoed command line and ends at the last row with content, so the trailing prompt is copied too. With them the copy is the command's output alone, even when the prompt repaints its line on Enter.

zsh emits the marks with one line in ~/.zshrc, before the prompt theme registers its own precmd hook:

precmd() { print -Pn '\e]133;D\e\\\e]133;A\e\\' }; preexec() { print -Pn '\e]133;C\e\\' }

dm reads these marks:

MarkWhat it tells dm
OSC 133;Athe prompt starts. Without a D mark, this is where the output ends.
OSC 133;Cthe command starts, and its output begins here. The copy starts here.
OSC 133;Dthe command ended. The copy ends here.

The marks are ordinary output, so they travel over ssh and a nested multiplexer like any other bytes. A shell on a remote host needs the same line in its own start file; a pane running a program instead of a shell has no prompt and no marks. dm reads the marks per pane and needs no configuration of its own.

The marks are defined by the semantic prompts proposal.
