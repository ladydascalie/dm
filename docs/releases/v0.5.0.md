dm 0.5.0 restarts a live session without a detach, and marks the page in the
bar.

Nothing a caller passes breaks in this release, though below 1.0.0 a minor may
change behaviour. One output line changed: `dm upgrade` now names the command
that makes an upgrade land.

## Restart without a detach

A session has always survived its server. The client did not: any close ended
it, so moving a session onto a new binary meant detach, `dm kill`, attach.

`dm restart -s <name>`, the `restart` action and `R` after the prefix do it in
place. The server answers, removes its socket and its pid file, tells every
client to reconnect rather than quit, flushes that frame through each writer,
and exits. Each client execs the binary on disk and attaches to the successor,
so both sides of the socket come back on the new build.

The panes never move. Every pane daemon keeps its process, its screen and its
scrollback, so the session you come back to is the session you left.

The screen does not flash. A restarted client inherits the alternate screen
instead of leaving it and entering it again, so the terminal saves your shell
once and gives it back once, when the session ends.

Two rules keep it honest. The socket goes before any client hears anything, so
no client can dial a server that is already leaving. And a client that resumes
early waits for the departing server's lock to clear instead of starting a
second server on the same session.

`dm restart` also takes a session whose server predates this release. That
server cannot be asked to leave in order, so it is stopped the way `dm kill`
stops it and the successor starts in its place. The first restart of a session
older than 0.5.0 therefore detaches its clients, and they come back when you
attach again. Every restart after that is seamless.

## The bar marks a live page

The daemon owns the web listener, so the snapshot carries its answer as `web`
and the status bar paints the mark while it is true: `◉` in the bar accent, at
the head of the pinned block, where a narrow bar drops it before anything you
have to act on. `w` stands in on a terminal whose font has no patched glyphs.

## Upgrading

```sh
dm upgrade
dm restart -s <session>     # or R inside the session
```

The session moves to the new build with its panes untouched. Panes keep the
binary their daemon started with, so pane code moves on the next close and
reopen, not on a restart.
