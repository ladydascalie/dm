dm 0.4.0 names a shelved pane, and lets the session serve its own web page.

Nothing a caller passes breaks in this release, though below 1.0.0 a minor may
change behaviour. One command changes shape: a bare `dm web` now prints the
URL the session already serves instead of binding a second listener on the same
address, and it only does that when `web-auto` made the daemon serve it.

## Names on the shelf

A shelved pane kept its id, its screen and its status, but nothing on the shelf
could say what it was for. The pane name already existed. The shelf surfaces now
set it.

- Double-click a chip in the shelf strip to rename that pane. The first press
  still selects the member, and the second opens the prompt.
- The shelf float's right-click menu carries `Rename pane`.
- The sidebar's shelf rows answer the same double click, and the row menu
  carries `Rename pane`, `Pop pane` and `Show shelf`.
- The prompt closes back onto the float, so the keys land on the member and not
  on a pane behind it.

The shelf's mouse rule has one exception now. A press on the sidebar's shelf
section belongs to the rail instead of putting the float away, because that
section names the shelf it would have closed.

## The session serves the page

A phone URL used to need a `dm web` in a pane, kept open only to hold a
process. The daemon is the process that is always there, so it can serve the
page itself.

- `web-auto true` in `config.kdl` starts the web listener with the session, on
  `web-addr`, with the token `web-token` pins or the one the session keeps in
  `web.token`. The URL survives a detach, a restart and a reboot.
- A bind that fails is logged and remembered, never fatal. The session runs
  without its page and the error is readable.
- `web-info` reports the listener the daemon holds right now, not the config
  flag. A `reload` that flips `web-auto` cannot make the answer lie.
- A bare `dm web` asks the daemon first and prints that URL, instead of binding
  a second listener on a port it cannot have. An explicit `--addr` or `--token`
  still binds its own, and with no daemon running `dm web` starts one as before.
- `U` opens a temporary float with the URL and its QR code, read from the
  daemon rather than from the config. The code is painted whole or not at all,
  and it needs 43 rows; a shorter terminal keeps the URL alone.
- `esc`, `q` or `U` closes the float. Every other key still reaches the pane
  under it.

Two limits are deliberate. A `reload` cannot start or stop the listener; only a
session restart can, so set `web-auto` before you start the session you want it
on. The daemon's listener is never read-only: pass `--read-only` to a manual
`dm web` when the page must not take input.

## The help overlay gained a row

The default key table gained `web-url` on `U`, and the overlay must still hold
the whole table on a 100x40 screen. `message box` and `notification centre` are
one float on two filters, so they share one row now. The card count is
unchanged, and the help frames and goldens follow.

## Upgrading

An installed binary keeps running until its session restarts. `dm upgrade`
installs the release, and a session started before it keeps the old build until
the server restarts. `web-auto` is read at server start, so a running session
needs a restart before the daemon serves its page.
