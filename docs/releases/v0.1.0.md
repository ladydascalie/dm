dm 0.1.0 is the first tagged release. It is one static Go binary that carries
the multiplexer, its session server, a CLI that scripts and agents drive, and a
phone page.

## Install

Download the archive for your platform from the assets below, untar it, and put
`dm` on your `PATH`. `checksums.txt` sits beside them, so `sha256sum -c` proves
the tarball first.

| platform | asset |
| --- | --- |
| linux, amd64 | `dm_linux_amd64.tar.gz` |
| linux, arm64 | `dm_linux_arm64.tar.gz` |
| darwin, amd64 | `dm_darwin_amd64.tar.gz` |
| darwin, arm64 | `dm_darwin_arm64.tar.gz` |

Linux and macOS only. There is no windows build, and there will not be one.

Run `dm provision` once in the checkout to link the pi extension and the fleet
skill into `~/.pi/agent`.

## What is in 0.1.0

- **Durable sessions.** The client owns the terminal, a server per session owns
  the layout, and a pane daemon per pane owns the shell. Detach, lose the
  client, or restart the server: the session comes back with its panes running.
- **Addressable layout.** Workspaces, windows and panes have typed ids (`s1`,
  `w2`, `w2p3`), splits, presets, named and saved layouts, and a rail that reads
  as the shape of the session.
- **A CLI for scripts and agents.** `dm split`, `dm write-to`, `dm read`,
  `dm exec`, `dm ls --json`, and a box that carries one-line state between
  agents.
- **Agent status.** OSC 7501 reports what a pane's program is doing, so the rail
  and the tab bar show working, waiting and blocked without polling.
- **Asks.** `dm ask` holds the questions an agent puts to the reader, and the
  client draws them in the TUI while the phone page lists them.
- **Phone page.** `dm web` serves the session over a token: layout, panes,
  typing, asks, and the QR path to get a phone onto it.
- **Secrets.** Registered by reference, fetched at use, redacted everywhere, and
  proxied when the upstream allows it.
- **Harness kit.** `dm provision` installs the pi extension and the fleet skill;
  `dm llms` prints the mechanical surface for any agent.
- **This release itself.** A tagged build carries its version. `dm version`
  reports it, `dm upgrade` replaces the binary after verifying the digest, and an
  attach tells you when a newer release exists.

## Updating

`dm upgrade` moves the binary you ran to the latest release. A session that is
already running keeps the old binary until it restarts. Set
`DM_NO_UPDATE_CHECK=1` to silence the boot notice.

## Status

0.x. The surface still moves between minor versions, and a minor may rename a
verb, a flag or a state file. The README is the reference for what exists now.
