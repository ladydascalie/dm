dm 0.3.1 ships the documentation work. The site now plays seven recorded
sessions, one per surface, and the recorder that makes them is one file per
demo.

No Go code changed in this release. The four tarballs carry the 0.3.0 binary
with a new stamp, so an upgrade moves no behaviour.

## Seven recordings

Each recording plays in the page: a still frame first, then the keys as they
land. A player opens paused, and `k` turns the key chips off and on.

The home page keeps two basics. A Demos page carries the rest.

| recording | what it teaches |
| --- | --- |
| split, project | the prefix box, a split, focus, and a workspace's project |
| windows | a second window, the digit that selects one, the preset layouts |
| panes | zoom, the shelf, and the float that goes back into the layout |
| scroll | scrollback, a live search, and a copy that toasts its count |
| dash | the dashboard over five panes, with filter, order and jump |
| palette | the command palette narrowing to one action and running it |

The player carries a 27KB webfont subset, so a reader whose terminal font
carries no patched glyphs sees the rail's icons instead of empty boxes. It
travels with the licence that the subset requires.

## One demo, one file

A cast is generated, so the recorder holds the recipe. Each demo is one file in
`scripts/casts/scenario/`: the screen size, the length and the keystrokes.
`scripts/casts/record.sh` holds what every demo shares.

Each demo records against its own scratch state and its own session, so
recordings run in parallel. The operator's sessions, config and theme never
reach a cast.

`scripts/casts/check.sh` fails a cast on five counts: the header, each event
line, at least one key, an empty last frame, and a codepoint the webfont cannot
draw. `record.sh` runs it after each recording, and `make docs-casts-check` runs
it over the tree with no terminal.
