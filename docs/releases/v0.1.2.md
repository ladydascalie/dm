dm 0.1.2 turns the documentation into a site, makes adding a harness one
adapter file, and takes one machine's paths out of every example.

## The documentation is a site

Every page the repo already keeps now renders at
https://darkmage.dev/dm/ with a sidebar, search, and light and dark themes: the
README as home, the internals tree in reading order, the release notes, the
plugin protocol and the four skills. `make docs-site` builds it locally and the
pages workflow deploys it. Nothing is copied by hand; a broken link or a page
missing from the navigation fails the build.

## A second harness is data, not a code path

`dm provision` used to hardcode two artefacts and refuse any harness without an
extension directory, so a skills-only harness could not be described at all. A
harness is now a name, a root and a list of mounts, and the installer names no
harness. pi remains the only adapter and behaves exactly as before.
`docs/internals/13-harnesses.md` is the design and the checklist, and a test
plans, applies and checks a harness that is not pi.

## Examples that run anywhere

The layout, action and secret examples named one home directory and one
directory convention. They now use `/home/you` and `~/src`, including the
strings compiled into `dm man`, `dm llms` and `dm html`. Fixtures and tests
followed.

## Updating

```sh
dm upgrade
```

A session that is already running keeps the old binary until it restarts.
