dm 0.2.0 makes a question reach the reader wherever it was asked, and keeps a
config error on screen after the toast has gone.

Nothing a caller passes breaks in this release, though below 1.0.0 a minor may
change behaviour. The two changes here are additions.

## A question finds the reader

An ask used to wait with no signal unless the reader stood on the pane that
asked. The desk draws the ask float on the focused pane of the active window,
so a question from any other pane, or any other window, waited unseen. The rail
badge was the only hint, and it is absent when the rail is hidden.

- Opening a question now gives its pane the focus, so the box stands in front of
  the reader.
- The status strip names the first question the desk is not showing, as
  `ask w1p1`, with the key that reaches it. It names the focused pane's own ask
  first and stays quiet while a box is up, since the key would hide that box
  rather than reach the other question.
- Answering leaves the screen where it was. The strip names the next question.

One question per store is still the rule, and answering one does not walk to the
next on its own.

## A load error survives the toast

A toast holds forty cells, elides its text and dies in three seconds, so the
line naming a broken config was unreadable after the flash.

A load failure now records its whole error in `config.kdl.error`, beside the
config file, and removes that file on the next clean load. `dm config` prints the
line, `dm config --json` carries it as an object for a script, and the client
toast points at the verb instead of truncating the error in the corner.

## Documentation

- The published site answers at https://darkmage.dev/dm/, one address in the
  README, the config page and the canonical links.
- The dm web example is a placeholder host, `you.ts.net:8099`, in the man page,
  `dm llms`, `dm html` and the config table. No example names a real host.
- The plugin contract states its two implicit rules: a plugin name may not
  collide with a built-in action, and a full-screen program is a plugin with no
  wrapper. `top` is the smallest worked declaration.
- The ask protocol page, the client page and the fleet skill now describe the
  focus a question takes and the key that reaches a queued one.

## Updating

```sh
dm upgrade
```

A session that is already running keeps the old binary until it restarts.
